# 项目周报

让读者快速看清本周主要做了什么、取得什么结果、还卡在哪里、下周准备推进什么。默认中文、简短要点为主；正文通常控制在 200–400 字，必要的对比表格另计，不为凑字数补充内容。用户给定的格式、范围和长度优先。

## 读取与取材

1. 按适用的 AGENTS.md 定位项目与记录入口，仅在路径或职责不清时读取 WORKSPACE。优先使用用户提供的材料，否则先读 Timeline，再只读相关 IMP 的 Detail 章节；不默认扫描全部历史、源码或日志。
2. 优先采用用户指定的日期范围。未指定时，“本周”取当地时间本周一至当前日期，“上周”取上一完整自然周；标题写明实际日期范围，未结束的一周注明截至日期。
3. Timeline 用于定位候选工作，不直接当作本周成果清单。IMP 编号日期是建档日期，Timeline 日期可能只是最近更新；结合 Detail 中的实验时间、阶段变化和结论确定本周增量。查询历史周时，仅在必要时定向查看对应归档、文档版本或已引用的 Artifact；无法确定时间归属的成果不冒充本周完成项，影响总结时简短说明记录缺口。
4. 按实际工作主线合并多个 IMP 和前后继阶段，通常保留 2–4 条重点。同一目标的多轮尝试归并为“主要动作与关键结果”；小修、重复检查、纯工具操作和无关支线不逐项展开，除非本身就是本周汇报重点。

只读取源记录；生成周报不新增 IMP、不修改 Timeline／Detail，也不触发初始化、训练或清理。未要求保存时，直接返回可复制的 Markdown；要求保存时沿用项目已有文档位置。

## 提炼与表述

- 每条主线一到两句，先写本周实际做的事，再写结果或阶段判断；保留一到两个最有说明力的数字即可。使用“完成、修复、验证、定位、确定”等具体动词，避免“持续推进、全面优化、取得显著进展”等空泛表述。
- 区分已完成、进行中和待验证。数据准备、冒烟测试、训练启动与最终质量通过分别表述；只在可比基线与候选结果均存在时写提升，保留决定结论的条件与限制。
- 已解决的难点并入对应成果；“难点与问题”只写仍影响后续工作的关键问题及其影响，合计一到两句。记录未报告阻塞时可写“暂无已记录的阻塞问题”，不为了填满栏目制造问题。
- “下周计划”从相关 Detail 的下一步和已有阶段计划中提炼优先动作与预期交付，合计一到两句。前置条件未通过时先写解决条件，不将后续阶段写成确定承诺；记录缺少明确安排时，将建议标为“建议”，不编造期限、负责人或已获授权的任务。
- 正文默认省略 IMP／EXP 编号、脚本名、路径、命令和调试过程；只有帮助读者判断交付或问题时才保留技术细节。需要追溯时再提供来源，不默认附长来源清单。

## 关键表格

- 有助于说明结果的已有对比表、指标表或阶段结果表，摘录或精简后直接贴在相关要点之后；不要只给文件链接。没有有用表格时省略，不强制把每条工作改成表格。
- 优先保留本周相关的关键行和列，通常三到五列、两到五行；不直接搬入 EXP 流水账、完整评估大表或产物路径清单。保留指标名、单位、基线／候选条件以及未测、不可比较等标记，不能为缩短表格删掉决定比较是否成立的条件。
- 原材料只有零散数字、但表格确实更清楚时，可依据记录整理成表；不可补造数据。不同评估口径不得拼成提升对比。
- 表格承载具体数值，文字解释动作与结论；同一组结果只展示一次，不在正文和表格重复罗列。

## 输出结构

```markdown
# 周报（日期范围；本周未结束时注明截至日期）

## 本周工作

- **主线名称**：本周主要动作与已确认结果。
- **主线名称**：本周主要动作与当前阶段。

## 难点与问题

一到两句概括仍未解决的关键问题及其影响。

## 下周计划

一到两句概括优先动作与预期交付。
```

关键表格按需插入“本周工作”的相关要点之后。不要添加重复的开头概述、结尾总结、自评或无内容的占位项；少量工作可只保留一条要点。

交付前检查：每项成果属于报告时间范围；同一主线没有拆成实验流水账；主要动作和结果都清楚；数字和阶段措辞忠于记录；表格与正文没有重复；问题和计划各不超过两句。
