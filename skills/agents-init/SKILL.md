# 项目初始化

充分理解当前项目后，建立精炼、长期有效的项目入口。

初始化仅负责调查、索引和文档；除非用户明确要求，不修改源码、配置、实验结果或现有目录结构。

## 调查项目

检查 README、配置、核心代码、文档、测试/评估入口和已有项目记录，确认：

* 项目目标和当前技术路线；
* 独立 Git 仓库、子项目及其职责；
* 自研、辅助、第三方/参考仓库的区别；
* 仓库间依赖、数据/模型/接口流向；
* 训练、推理、测试、部署等主要工作流；
* 重要约束和已有设计决策。

不要根据目录名直接推断。用代码和文档验证关键结论。

已有 `.codegraph/` 时优先使用 CodeGraph 探索，再按需读取具体文件。

## CodeGraph

对需要长期查阅代码的项目或独立仓库：

* 没有 `.codegraph/`：执行 `codegraph init`；
* 已存在：不要重复初始化；
* 失败或命令不可用：记录未完成并继续。

只在对应代码根目录初始化。

## AGENTS.md

`AGENTS.md` 只保留未来 Agent 高频需要的工作规则：

* 项目目标和核心约束；
* 操作、测试、数据、评估和部署规则；
* 不可轻易推断的重要约定；
* 使用的 skills；
* `WORKSPACE.md` 和其他关键导航入口。

不要复制 README、WORKSPACE 或源码中容易发现的信息。

不要把频繁变化的实验状态、指标、模型版本写入 AGENTS。

## WORKSPACE.md

对于存在多个仓库、子项目或复杂目录的项目，创建或更新 `WORKSPACE.md`。

它负责记录：

* 仓库和主要子项目的位置；
* 各自职责和来源；
* 哪些可修改、哪些是第三方参考；
* 仓库之间的关系和主要数据流；
* 共享资源、模型、实验记录和重要产物的位置；
* 常见任务应该去哪里找。

只记录稳定的结构和导航信息，不记录具体实验过程。

## Existing files

已有 `AGENTS.md` 或 `WORKSPACE.md` 时先阅读并保留仍有效的用户约束，按当前项目事实增量修正。

不要为了统一格式而重构第三方仓库或独立子项目。

## 完成检查

确认：

* AGENTS 与 WORKSPACE 职责没有重复；
* 项目地图与实际目录一致；
* 多仓库边界和关系清楚；
* CodeGraph 状态明确；
* 没有模板占位符或未经验证的推断。

完成后简洁汇报生成/更新内容及未完成项。

**原则：调查充分，入口精简。**
