# 项目初始化

充分理解项目，建立长期有效的规则与导航入口。初始化只负责调查、索引和文档；未经用户要求，不修改源码、配置、实验结果或现有目录结构。

## 调查

1. 先阅读适用的 AGENTS.md 和已有 WORKSPACE.md，保留有效的用户约束；进入子仓库时检查局部规则。
2. 确定整个工作区的根目录，不把当前终端目录或某个 Git 根目录直接当作整个项目边界。
3. 检查 README、配置、核心代码、测试／评估入口和已有记录，确认项目目标、技术路线、主要工作流、约束与设计决策。
4. 识别独立仓库、子项目及自研／辅助／第三方参考关系，验证职责、依赖与数据／模型／接口流向；不要只按目录名推断。

调查达到能解释各仓库职责、主要流程和常见任务入口即可，不逐文件通读，不读取无关的大型数据、权重和日志。无法验证的事项标为待确认。

## CodeGraph

- 已有可用索引时优先辅助定位，再读取相关源码核实；目录存在不代表索引仍有效。
- 对需要长期查阅的代码根目录，没有 `.codegraph/` 时执行 `codegraph init`；避免在工作区父目录与子仓库重复索引同一代码。
- 已有索引不重复初始化；发现相关索引陈旧时，按工具实际支持的方式更新，不猜测命令。
- 命令不可用或失败时记录未完成，继续调查，不阻塞文档初始化。

## AGENTS.md

只保留未来 Agent 高频需要的稳定规则：项目目标、核心约束、操作与验证约定、不可轻易推断的设计限制，以及 WORKSPACE 和记录入口。

文档分工保持明确：AGENTS 维护长期协作约定，WORKSPACE 维护边界与位置，Detail 维护实际进展和决策，Timeline 摘要引用；已有 plan 维护阶段顺序和验收门槛，通过记录入口引用实际进度。

写明简短的维护约定：

- 实质改进或实验结束后，用 `project-improvement-tracker` 更新 Detail，再更新 Timeline。
- 仓库职责、结构或重要资源位置变化，以及工作区整理任务，用 `workspace-manager` 维护。
- 日常生成文件遵守 WORKSPACE 中已有的归置与保留规则，不为每个文件重新调用管理 skill。
- 长期工作约定变化时增量更新 AGENTS，无须重新初始化。

仅登记实际可用的 skills；缺少配套 skill 时记录缺项，不自动安装。通用管理流程引用对应 skill，AGENTS 保留项目入口与特有约束；不要复制 skill 全文、README 或 WORKSPACE，也不要写入频繁变化的指标和模型版本。

## WORKSPACE.md

多仓库或复杂项目建立工作区根目录下的 WORKSPACE.md；单仓库简单项目可在 AGENTS 中保留简短入口，不强制增设文件。

沿用现有导航；可用时参考 `workspace-manager` 的格式，确定：

- 工作区根目录，各仓库的固定简称、相对路径、职责、来源、修改策略和关键入口。
- 主要依赖与数据流；常见任务应去哪个仓库、入口文件或子目录。
- Timeline／Detail 的唯一主入口，以及模型、共享资源、实验结果、临时产物、保留成果的实际位置。
- 项目采用的命名、归置、保留和清理约定；区分受保护成果与可清理临时产物。

路径文本相对工作区根目录，Markdown 链接相对所在文档；外部资源明确标为外部位置。跨仓库改进使用一份主记录，各仓库引用它。

优先复用已有位置；没有记录入口时选择一个简短位置登记，记录文件待首次实际使用再创建。分类不要求各建一个目录，不创建空目录或重构第三方仓库。

## 完成

增量修改已有文档，保留有效约束。检查入口和路径正确、仓库边界清楚、规则与地图不重复、没有遗留占位符。简洁汇报更新内容、主要入口及未完成项。
