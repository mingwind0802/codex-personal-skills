# 项目初始化

充分理解当前项目后，建立精炼、长期有效的项目入口。

初始化仅负责调查、索引和文档；除非用户明确要求，不修改源码、配置、实验结果或现有目录结构，也不预先创建空目录。

## 先读已有规则

先阅读适用的 `AGENTS.md` 和已有 `WORKSPACE.md`，保留仍有效的用户约束。进入独立仓库或子目录时，继续查找并遵守其局部 `AGENTS.md`。

## 调查项目

检查 README、配置、核心代码、文档、测试/评估入口和已有项目记录，确认：

* 项目目标和当前技术路线；
* 独立 Git 仓库、子项目及其职责；
* 自研、辅助、第三方/参考仓库的区别；
* 仓库间依赖、数据/模型/接口流向；
* 训练、推理、测试、部署等主要工作流；
* 重要约束和已有设计决策。

不要根据目录名直接推断。用代码和文档验证关键结论。

已有 `.codegraph/` 时优先使用 CodeGraph 探索，再按需读取具体文件。

## CodeGraph

对需要长期查阅代码的项目或独立仓库：

* 没有 `.codegraph/`：执行 `codegraph init`；
* 已存在：不要重复初始化；
* 失败或命令不可用：记录未完成并继续。

只在对应代码根目录初始化。

## AGENTS.md

`AGENTS.md` 只保留未来 Agent 高频需要的工作规则：

* 项目目标和核心约束；
* 操作、测试、数据、评估和部署规则；
* 不可轻易推断的重要约定；
* 使用的 skills；
* `WORKSPACE.md` 和其他关键导航入口。

加入简短的维护触发约定：

* 完成实质改进或实验，调用 `project-improvement-tracker` 更新记录；
* 仓库结构、职责或重要资源位置变化，调用 `workspace-manager`；
* 生成文件遵守 `WORKSPACE.md` 的归置和保留规则；
* 稳定工作规则变化时增量更新 `AGENTS.md`，无须重新初始化。

只写触发约定，具体流程留在对应 skill。不要复制 README、WORKSPACE 或源码中容易发现的信息，也不要记录频繁变化的实验状态、指标或模型版本。

## WORKSPACE.md

对于存在多个仓库、子项目或复杂目录的项目，创建或更新 `WORKSPACE.md`。确定并记录实际适用的约定：

* 工作区根目录：整个项目的导航起点；
* 仓库身份：每个仓库的固定简称、相对路径、职责和修改策略；
* 记录入口：Timeline、Detail 的实际位置，优先复用已有结构；
* 产物位置：临时产物、实验结果、保留版本和共享资源的实际位置及规则；
* 路径规则：WORKSPACE 中路径相对工作区根目录，Markdown 链接相对所在文档。

同时记录仓库来源、关系、主要数据流和常见任务入口。只登记项目实际需要且已经存在或确认要使用的位置，不预先创建空目录；只记录稳定结构和导航，不记录具体实验过程。

## Existing files

已有 `AGENTS.md` 或 `WORKSPACE.md` 时按当前项目事实增量修正，不为了统一格式重构第三方仓库或独立子项目。

## 完成检查

确认：

* AGENTS 与 WORKSPACE 职责没有重复；
* 项目地图、固定简称、记录入口和产物位置与实际目录一致；
* 多仓库边界、关系和路径规则清楚；
* CodeGraph 状态明确；
* 没有空目录、模板占位符或未经验证的推断。

完成后简洁汇报生成/更新内容及未完成项。

**原则：调查充分，入口精简。**
